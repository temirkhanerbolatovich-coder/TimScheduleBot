# Интерфейс расписания в Telegram

Главное меню — кнопки под полем сообщения. Команды для повседневной работы вводить не требуется.

| Кнопка | Действие |
|---|---|
| 📅 Сегодня / 🌅 Завтра / 🗓 Неделя | Планы на выбранный период; «Неделя» показывает ближайшие семь дней |
| 📋 Мои записи | Список с выбором записи и переходом между страницами |
| ➕ Добавить планы | Подсказка для ввода одного плана или всей заметки |
| ⚙️ Сводки | Время ежедневных уведомлений, день и время недельной сводки, включение и отключение |
| ❓ Помощь | Примеры заметок и объяснение кнопок |
| ↩️ Отмена | Отмена текущего ввода и неподтверждённого изменения |

Если клавиатура скрыта самим Telegram, открой её значком клавиатуры возле поля сообщения. `/start` снова показывает меню. Постоянная клавиатура отправляется при просмотре сводок и после завершения действий; кнопки управления отдельной записью расположены непосредственно под её сообщением.

## Как выглядят сводки

Названия и дни выделены жирным. Вместо технических номеров используются названия событий. Повторяющееся описание смены убрано; кабинет и преподаватель из поля вида «402А, Преподаватель Г» показаны отдельными строками. Остальные пояснения сохраняются без догадок об их значении.

Пример для исходных записей владельца:

**Среда, 14.10**

🌙 **Продолжение: ночная смена**  
🕒 До 08:00 · началось 13.10 в 20:00

☀️ **Дневная смена · 6 часов**  
🕒 08:00–14:00  
ℹ️ заменяет коллегу

📚 **Работатехника**  
🕒 11:00–14:00

📚 **Английский**  
🕒 14:00–17:00  
📍 Кабинет 402А  
👤 Преподаватель Г

📚 **СУБД**  
🕒 15:00–18:00  
ℹ️ Казахстан

⚠️ **Пересечение 11:00–14:00**  
Дневная смена · 6 часов ↔ Работатехника

⚠️ **Пересечение 15:00–17:00**  
Английский ↔ СУБД

Продолжение ночной смены отображается в обоих днях, поскольку занимает время в обоих. У смены с нестандартной продолжительностью количество часов в названии соответствует фактическому интервалу. Опечатки и названия предметов бот самостоятельно не исправляет.

## Изменение записей

1. Нажми «📋 Мои записи», затем выбери нужную запись.
2. Нажми «Перенести», «Изменить», «Удалить» или «Завершить».
3. При переносе введи только дату и время: `15.10.2026 18:00`. При редактировании введи новое название, время и описание. Если дату разовой записи не указать, сохраняется прежняя; для регулярной записи сохраняется прежний день недели. Новый день можно указать заголовком на отдельной строке.
4. Проверь предпросмотр и нажми «✅ Сохранить».

Для регулярного занятия есть отдельные кнопки переноса или отмены одного повторения. Дату выбирай среди ближайших четырёх недель; остальные недели сохраняются. Более далёкая дата доступна через существующую команду `/override` или `/skip`. Уже отменённое повторение не показывается в списке; у перенесённого видна новая дата. Удаление серии удаляет её исключения и требует подтверждения. Редактирование серии с исключениями блокируется, как и в прежней версии.

Новое изменение или новый сценарий ввода заменяют предыдущий неподтверждённый черновик. Двойное нажатие «Сохранить» не повторяет изменение. Неправильный ввод не меняет расписание: можно исправить текст или отменить ввод. Для новых планов текст заметки всё ещё нужен: кнопка показывает подсказку, а не создаёт неизвестное расписание автоматически.

В «Сводках» доступны готовые часы; своё время можно отправить в формате `ЧЧ:ММ`. Настройки уведомлений применяются сразу. Перенос, редактирование, удаление и завершение событий требуют отдельного подтверждения.

## Устройство и проверка

Существующий Python, SQLite и polling сохранены. Кнопки главного меню используют `ReplyKeyboardMarkup`; действия с записью — `InlineKeyboardMarkup` и callback. Callback подтверждается через `answerCallbackQuery` до выполнения действия. Доступ проверяется по владельцу и личному чату; событие выбирается только из его записей.

Состояние ожидаемого ввода хранится в новой таблице `ui_states`, поэтому перезапуск не теряет выбранный сценарий. Миграция только добавляет таблицу; существующие планы, настройки, исключения и привязка не перезаписываются. Резервное копирование SQLite включает эту таблицу.

Текст пользователя экранируется для HTML. Длинные сообщения разделяются с сохранением корректных тегов, сущностей и Unicode; клавиатура прикрепляется к последней части. Зависимости для интерфейса не добавлены.

`python3 -X utf8 -m unittest -q` проверяет меню, страницы, перенос и редактирование, подтверждения, отмену, исключения серии, настройки, сохранение ввода после перезапуска, чужие и некорректные callback, экранирование и разделение длинных сообщений.

При разработке использован навык `telegram-bots-dotnet`, опирающийся на [TelegramBots/book](https://github.com/TelegramBots/book). Применены общие правила Bot API без переноса Python-бота на C#: [клавиатуры и callback](https://telegrambots.github.io/book/2/reply-markup.html), [форматирование сообщений](https://telegrambots.github.io/book/2/send-msg/), [официальные ограничения API](https://core.telegram.org/bots/api).
